# Textbook Knowledge Extractor (audit contract v2.4)

Produce a traceable transcription of the requested range. This is extraction, not summarization: do not add knowledge, explanations, proofs, or improvements absent from the source.

Defaults are Chinese output with first-occurrence mathematical terminology as `中文（English）`; explicit user or case settings override defaults. Inline math uses `$...$` and display math uses independent `$$` lines only. Validate the completed package with `scripts/check_math_rendering.py` and record the result in `audit.json.render_validation`.

## Mandatory workflow

Follow these phases in order. Do not begin full-source reading before phase 2 has produced a verified slice.

1. **Understand the task.** Restate internally the source, requested chapter or section, output language, required block classes, exclusions, exemplar conventions, and deliverables. Resolve material ambiguity before extraction.
2. **Define and inject the scope.** Run `python -X utf8 scripts/scope_markdown.py index ...` from the skill directory or use the path supplied by the benchmark harness so only the compact heading index, line numbers, and optional short prefixes enter context. For unfamiliar or converted sources, run `precheck --source <book.md>` before extraction; it is advisory and never edits the source. Select the requested start heading from that evidence, then run `extract` to create a chapter-only slice and scope manifest. If a reliable probe or external boundary decision supplies line numbers, use `extract --start-line N --end-line M` (1-based inclusive; the start line must not be inside a fenced code block); a heading start may be combined with `--end-line`. For nonstandard sources: `index --loose-atx` surfaces `#` markers without a space (tagged `matched_by=loose`), and heading parameters tolerate a `#` prefix or extra whitespace. Read the slice, not the whole book. Read [references/spec/extraction-policy.md](references/spec/extraction-policy.md) for exact fallback, damage-ledger, classification, and boundary rules.
3. **Complete the extraction.** Build a complete candidate inventory, including unnumbered prose and mixed blocks. A candidate is a source container (or an explicitly recorded subspan), not an item generated by an undisclosed checker. Apply the ordered unlabeled-prose test and record every non-obvious choice in `audit.json.extraction_judgments`. For source-labeled examples, retain setup/result but split and exclude derivation or proof spans unless the case explicitly opts in. Transcribe retained blocks in source order; when source order conflicts with numbering, preserve source order and register an `order_artifact`. Preserve mathematical meaning, numbering, and LaTeX. Same-language work should copy source wording; requested translation must not compress or embellish.
4. **Self-accept.** Read [references/spec/acceptance-standard.md](references/spec/acceptance-standard.md). Ask the benchmark harness to run its deterministic selfcheck before each round and retain the resulting checklist. The selfcheck verifies declared inventory closure, spans, hashes, order, structure, and leakage; it must not invent an `expected` candidate set. Then score and check the actual artifacts against the source slice and inventory, including hard gates.
5. **Revise or submit (four-step round reconciliation).** At the start of every round, (a) read `runlog.md` and the previous round's defects, (b) claim each defect as **repaired**, **refuted**, or **not applicable**, with evidence, (c) rerun the complete `selfcheck.py` and acceptance checks, and (d) append newly observed failures to `runlog.md`. Submit only after a pass. After three total acceptance rounds, stop with failed checks and evidence rather than claiming completion.

For benchmark tasks, read the benchmark package README and prompt supplied by the harness.

In v2.3, run the candidate-discovery command after slicing. Its generated inventory is authoritative: assign decisions to every unit and do not invent, remove, merge, or renumber candidates. Structural selfcheck status must be reported separately from content-coverage and human-review status.

This skill is self-contained. From its directory use `scripts/scope_markdown.py` and `scripts/schema_check.py`; benchmark-specific validators are invoked by the benchmark harness and are not imported here.

## Run log

Each run directory should contain `runlog.md`. Append one record per
deterministic failure or repair using this sequence: **trigger** (verbatim
program message and exit code) -> **root cause** -> **lesson** (an absolute
rule) -> **evidence** (file, line, hash, or selfcheck item) -> **verification**
(the rerun command and result). Do not replace a failed program check with an
AI explanation; the log is a compact, append-only handoff between rounds.

## Output contract

- The main artifact contains the range note followed by the extracted knowledge list only.
- Preserve examples, counterexamples, and remarks as required blocks.
- Exclude teaching commentary, proof sketches, derivations, solution strategies, exercises, and facts outside the verified slice.
- Keep scope evidence, candidate decisions, and acceptance results in the audit artifact, not in the reader-facing list.
- `source_start_line` is always the container marker line: ATX heading, Setext title text, opening fence, first callout marker, `<table>`/first `<tr>`, or first non-empty line for an uncontainerized paragraph/formula. `source_end_line` includes the closing marker. Record the corresponding `source_position` (marker and content lines) in audit; do not choose a content line ad hoc.
- When the source contains conversion damage, include the standard `source_artifacts` ledger in the audit. Repeated damage may be one `granularity="pattern"` entry with `pattern`, `count`, representative original text, occurrence lines/ranges, action, and evidence basis; unique or high-risk damage remains an item entry. Never silently repair.
- For a line that mixes retained result/setup and excluded derivation, use overlapping `source_subspans` with 1-based half-open Unicode code-point columns (`start_column`, `end_column`) and explicit roles/decisions. Do not duplicate an entire line without recording the subspan boundary.

## Knowledge-list structure

Mirror the source hierarchy in `knowledge.md`: range note, source chapter heading, real source subsection headings (such as 2A/2B/2C), then K blocks in source order. Do not invent summary headings. K headings identify blocks and do not replace source section headings. A block crossing sections is placed by its marker line and noted in audit.

## Extension boundary

This skill does not decide whether a proposition or exercise is provable from the extracted list. A disabled draft handoff contract is documented at `../../interfaces/proposition-provability-v0.1-draft.md` for a future dedicated provider; do not invoke it or generate provider artifacts unless a later case explicitly enables a separately implemented skill.

## Stop conditions

Stop and identify missing evidence when the source is unavailable, the requested range cannot be uniquely located, relevant text is truncated, the scope tool cannot parse a reliable boundary, or output cannot be read back. A plausible reconstruction is a failure.
